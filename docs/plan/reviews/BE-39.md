Verdict: **Request changes**. Date: 2026-10-19. Fix on `be/BE-39-contract`.

**Merge with the base first** (`git merge origin/feature/v2-backend`; history rewrite is not needed). If `docs/architecture/v2-backend-deviations.md` conflicts, keep the base file and **append** your rows; do not create the file again. Then run `npm run contract:emit` and set the tracker row to `review`.

The paper-builder mock lives in the prototype (src/modules/m28-bijak-spm/{server/admin.ts, domain/admin-types.ts, domain/paper-builder.ts, admin/papers}). It is not on GitHub yet. The findings below quote it; copy those field names, statuses and BM strings exactly.

## Must fix

- docs/architecture/v2-backend-deviations.md already exists on base but this branch adds it as a new file. Rebase and append the BE-39 rows to the existing file instead of re-creating it.
- The publish success shape differs from the mock. The mock publishPaper returns { ok: true, errors: [] } on success (server/admin.ts:~840). The contract's BijakBuilderPublishResult is a strict union whose ok:true arm is { ok: true } with no errors key. A mock-shaped success payload fails strict parsing, and the test fixtures encode the wrong shape. Use { ok: boolean, errors: string[] }, with errors empty on success.
- BuilderQuestion does not match the mock. The mock fields are id, groupId?, stimulusLabel?, preview, marks, kind (QuestionKind), topic, status, kertas, subject. The contract has id, stem, topic, marks, groupId?, so preview, kind, status, kertas, subject and stimulusLabel are missing and stem is invented. The review (round 2) asked for fixtures taken from the mock.
- BuilderGroup does not match the mock. The mock is { id, stimulus: StimulusDef, questionIds }. The contract is { id, label, questionIds.min(2) }, with the stimulus object replaced by a label string. The picker cannot render stimuli from this.
- getPaperEditor (PaperEditorData) lacks the mock's `blueprint: BlueprintView | null`. The contract's BijakBuilderEditor is { paper, questions, groups } only.
- AdminPaper does not match the mock. The mock AdminPaper extends PaperDef, so it carries instructions and reference, createdAt, publishedAt?, and per-section questionCount. The contract strict object omits these and adds code and checks, which the mock does not expose on AdminPaper (the mock keeps checkOf server-side). If checks is kept it must be declared as a deviation row, and instructions, reference, createdAt and publishedAt are still missing.
- AdminPaperSummary does not match the mock. The mock list row has subjectName and code. The contract summary (paperSummaryShape) has neither; code is only on the full paper.
- BlueprintView does not match the mock. The mock fields are subject, subjectName, kertas (1|2), source, code, durationMin, instructions[], totalMarks, and sections[] each with label, markBudget, questionCount, compulsory (boolean), instruction (string), rule and pool. The contract view adds id, version and status (there is no mock for these). It drops instructions and totalMarks. It renames questionCount to take and makes compulsory and instruction optional. It omits pool, although the mock builder uses pool to suggest questions. The 'no pool tags' decision contradicts the mock.
- The preview shape and path differ from the mock. The mock is previewQuestions(ids: string[]) returning { questions: ReviewQuestion[], stimuli: Record<groupId, StimulusDef>, optionBanks: Record<groupId, McqOption[]> }, called with the unsaved ids currently in the editor (PaperEditorPage.vue:207). The contract has GET /admin/papers/{id}/preview returning BE-16 { questions, groups } for the saved paper only. The editor therefore cannot preview unsaved edits, and the result type is not the mock's.
- Error status codes differ from the mock for the locked paper, delete of a terbit paper, and the 422 versus 400 cases. The mock throws 'bad_request' for all of them. The contract uses 409 CONFLICT and 422 with fields. These are marked [PROPOSED] but are not listed as a deviation or confirmed by the LEAD. The status and code mapping needs the LEAD's decision before the error code is wire-fixed. The routes are marked [PROPOSED] for 409, so Major rather than Blocker.
- createPaper validates a missing blueprint as 422 fields.subject. The mock throws bad_request 'Tiada blueprint untuk subjek dan kertas ini' with no field. PaperPatch 'Soalan tidak sah' in the mock is a subject check only (`q.curriculum.subject !== paper.subject`), not a kertas check or a published-question check. Check that the description matches; the route text says 'a question that cannot go on this paper'.

## Minors

- The unpublish route is POST /admin/papers/{id}/withdraw, returning the paper. The mock method is unpublishPaper returning void. The path name follows the card, which is fine, but the response differs from the mock (void) and the deviations log should say so.
- The mock listAdminPapers and listBlueprints return plain arrays. The contract uses the paged listEnvelopeOf, which is correct for the common pagination convention. Note it as a deviation row.
- The tests use hand-built payloads, not fixtures lifted from the mock (the round-2 minor is still open). They also lock in wrong shapes: publish {ok:true} without errors, BuilderQuestion.stem and BuilderGroup.label. Rewrite them after the shapes are aligned.
- The header comment in schema.ts still says the mock is not pushed and the shapes follow the review quotes. The mock is available now, so the MOCK STATUS and D58b [PROPOSED] wording should be updated and the quoted copy confirmed against server/admin.ts. The six quoted strings do match the mock verbatim: 'Kertas tidak ditemui', 'Kertas Terbit tidak boleh disunting. Tarik balik dahulu.', 'Tarik balik kertas Terbit sebelum memadam', 'Tajuk kertas diperlukan', 'Soalan tidak sah untuk kertas ini', 'Bahagian tidak sah' and 'Tiada blueprint untuk subjek dan kertas ini'. The mock BM also has the checkPaper lines (e.g. 'Kurang N soalan (perlu X, ada Y)', 'Markah M tidak sama dengan bajet B', '{N} soalan belum Terbit', 'Kumpulan rangsangan G tidak berturutan' and 'tidak lengkap'), but the contract documents an invented example, 'Bahagian A: perlu 3 soalan, hanya 2 tersedia', in the publish description. Replace it with the real lines; the publish errors are prefixed with '{label}: '.
- The endpoint set otherwise covers the card, minus the three removed routes (documented), with no invented extras beyond the preview GET and the withdraw POST. The five blueprint routes are card-required with no mock (documented as such). Ids use IdSchema, the shared error envelope, envelopeOf and listEnvelopeOf, CSRF and the D57 429 helper. No secrets or real person names were seen.
