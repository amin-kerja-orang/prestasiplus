The green results above do not apply to the merged tree until this is done.
- **Major:** The tests do not use payloads taken from the mock. The success payloads (post, detail, profile, class dashboard, school) are hand-written 'Contoh' fixtures. No test parses what the mock handlers or repositories actually return, so a shape drift against the mock would not be caught. The test file does cover the BM validation messages, the 30 registered paths and the rejection cases well. Add a few payloads captured from the mock output for the main reads: analytics/me, performance/classes/:id, rankings, headcounts/:id and students/:userId.

Minors:
- All 30 mock routes are covered with the mock's method and path, and the BM and error copy match the mock handlers. Nothing is missing or invented. The 403 vs 404 split follows the mock: item-analysis/classes/:id returns 403 for an unknown class, performance/classes/:id returns 404, and headcounts return 404 before 403.
- Scope is clean: only the card's reports/performance folder, the append-only lines in index.ts and openapi.ts, the regenerated openapi.json and the card's own tracker row changed. The path is reports/performance/{schema,paths}.ts, whereas the card text says reports/performance.ts. AGENT-SYNC row 73 says `reports/performance/**`, so this is acceptable. Update the card text if you want the two to agree.
- UD-1 is applied loosely in the create requests. classroomId, subjectId, educationLevelId and studentIds are `z.string().min(1)` instead of IdSchema or a decimal-string pattern, so 'abc' passes the schema. The mock accepts digit strings and numbers (form posts), so this is deliberate to some degree, but add a regex or comment it. Auto-setup `levels` accepts any non-empty string, while the mock only accepts D1..D6 and T1..T5; a regex would let 'X9' fail with 'Tingkatan tidak sah.'.
- Quote style is mixed: schema.ts has double-quoted strings in the headcount and timeline request schemas, but the rest of the repo uses single quotes. eslint printed nothing, so this is cosmetic.
- Photo type and size errors ('Gambar tidak sah (JPEG, PNG atau WebP, maks 2MB).') cannot be expressed in zod. They are documented only in descriptions and the limits constant, so the backend must enforce them. This is acceptable for a contract.
- Timestamps use the MYT-offset TimestampSchema, while the mock emits Z ISO strings for timeline createdAt. This follows the contract convention and a test covers it. Just keep the mock-to-contract difference in mind when the frontend switches over.
