## Security review (Fail)

Fix in the contract now every finding marked "contract now" with severity High or Medium. Items marked "implementation" go to the full card later.

- HIGH (contract now): GET /admin/config/defaults returns schoolAdminDefaultPassword, bulkImportDefaultPassword and compStudentDefaultPassword in clear. The schema itself carries 'OQ-API-B1-16: confirm exposing them'. A shared default password for minors' accounts is a credential in a response body. The path declares no Cache-Control: no-store and no must-change-password flag. D55(c) allows a plain password only once, for one created account, to the creating admin. It does not cover standing defaults.
- HIGH (contract now): GET /students/search is open to any signed-in role, with no scope. The query is a name-or-e-mail substring from 2 characters. It returns name, classLevel and schoolName of minors, up to 15 per call. Any student, parent or sponsor can enumerate children across all schools. The path has no 429 and no role or scope restriction.
- HIGH (contract now, decision needed): UserRolesSchema accepts every ROLE_CODES value on POST and PUT /admin/users, including admin and ppd_officer. Card rule 10 says school_admin is allowed on some routes 'where the mock allows'. The contract does not say which routes those are, and does not restrict assignable roles by caller. A school_admin who can create or update users could create an admin account (privilege escalation) or move users to another schoolId. There is also no guard against an admin demoting, deactivating or toggling themselves or the last admin. Only self-delete is blocked (422).
- HIGH (contract now, new endpoint-level text): none of the 20 or so BE-05 operations documents a 429 RATE_LIMITED response, even though BE-NFR-04, BE-NFR-22 and D55(a) set the pattern. Missing on POST /admin/users, PUT, bulk-delete, bulk-import, toggle-active and POST /admin/schools. Also missing on the unauthenticated GET /schools/search, /jpn and /jpn/{id}/ppd, and on /students/search. The write limits have no source in the URS (OQ-9). The contract needs at least the response shape and Retry-After header, with numbers set in BE-05.
- MEDIUM (contract now): bulk-import has no cap. The schema says 'The mock sets no file-size or row limit'. A single JSON string field (csvFile or pasteContent) has no max length, no max row count and no multipart size limit. That is a memory and CPU DoS. Each row can carry a password, hashed with a slow KDF per row. Add a max length and max rows (for example 1 MB or 1000 rows) and 413/422 and 429 responses. Rate limit the import tightly.
- MEDIUM (contract now): passwords in requests have a minimum (6) but no maximum (password, newPassword, defaultPassword, per-row CSV password). An unbounded string into a slow hash is a DoS vector, so add max(128). A 6-character minimum is weak for accounts of minors. It is the mock rule, so raise the policy as an open decision. Also state that password fields are never echoed in 422 `fields` or error bodies, and never logged (BE-NFR-27).
- MEDIUM (contract now): no response documents Cache-Control: no-store (BE-NFR-40). Every user, student, school-student and import-report response carries personal data of minors. The contract can carry this as a description line or response header on all operations, and the implementation adds a global interceptor. Nothing in the contract tests for it.
- MEDIUM (contract now for the shape; implementation for the rule): e-mail enumeration through unique checks. Create, update and import return a distinguishable 422 'The email has already been taken.' for email, username (unique per school) and school code. Import `skipped` and per-line errors also reveal which e-mails already exist. For an authenticated admin this is acceptable, but with a school_admin caller it is a cross-tenant oracle that tells them an e-mail exists in another school. Recommend: the message may stay for admin; for school_admin the uniqueness error must not reveal that the account belongs to another school. Apply D55(b) to any public path. The contract should state which callers see the distinct message.
- MEDIUM (contract now): scope and information leakage for admin vs school_admin. The contract only says 'FORBIDDEN (not an admin)' and never states scope. The user list and detail, /admin/teachers (all teachers with e-mail, no scope), /admin/schools/{id}/students (e-mail, idDelima of minors), /admin/schools/{id}, AdminSchool.joinCode (a bearer secret for enrolment), roleCounts (global counts) and /admin/users/filters (global school list) are all unscoped in text. If school_admin is a caller, each must be scoped to their own school. An out-of-scope id must return 404, not 403, so ids cannot be probed. Put an explicit role/scope table per operation in the paths.
- MEDIUM (contract now): D55(c) must-change-password is not in the wire. AdminUserDetail and the create/import responses have no mustChangePassword flag. Accounts created through bulk-import with the shared default password, and password changes by an admin on PUT (newPassword), also have no flag. Sessions of the target user are not stated as revoked on password change, deactivation or role change (BE-NFR-39 covers part of it). Add the flag to the detail and state the revoke.
- MEDIUM (implementation card; contract note): PDPA and minors. AdminUserDetail exposes phone, bio, grade, lastLoginAt, linkedStudents, and e-mail in the list, with no audit of reads. DELETE and bulk-delete are hard deletes with cascade (the mock cascades parent links, invites, packages and sessions). Erasure and retention have no rule (OQ-3). Recommend audit rows for detail reads, bulk-delete and import, with ids and counts only and never personal data in audit content. Confirm that cascade delete does not orphan data of other modules. Rights to access, correction and erasure need an owner. It is acceptable to defer to OQ-3 but record it.
- LOW (contract now): the IC. icNumber is max 14 with no format rule, so malformed input is accepted. Responses correctly return icMasked only. icMasked still shows the last 2 digits, which is acceptable. The validation error must not echo the submitted IC value. An IC is a 12-digit space, so the stored hash is brute-forceable if it is a plain hash. Implementation must use a keyed HMAC (server secret/pepper), not an unsalted hash, and must use it for the D55(a) reset-ic comparison. The log-capture and DB-dump tests (card AC5) cover this.
- LOW (contract now): GET /schools/search is public and its `limit` has 'no maximum', which violates BE-NFR-16 (max 100). It allows a full dump of the school list. The data is public school names and codes, so impact is low, but cap the limit at 100 and add 429. Public routes /jpn and /jpn/{id}/ppd are fine. joinCode is correctly absent from the public SchoolSummary.
- LOW (contract/implementation): looseBool (true, 1, '1', 'on', 'yes') is a mass-assignment style coercion on isActive and is never rejected. Strict request schemas (BE-NFR-25) conflict with that. Unknown keys must be rejected, so that roles, icHash or joinCode cannot be set (the SchoolInput note says joinCode is never accepted, which needs a strict object). The detail response exposes landingPath, ppdState and ppdDistrict, which are fine. Bulk-import CSV echoes names only in errors by line number, which is good. Formula injection (BE-NFR-38) applies to any future export, not to this import.

Recommendations:
- Fix in the contract now (before merge): (1) remove GET /admin/config/defaults from the wire, or return only booleans or 'configured', and move the OQ to a decision. Mark the response no-store. (2) Add a per-operation role and scope table, and restrict assignable roles and schoolId for school_admin (never admin, ppd_officer or another school). Specify 404 for out-of-scope ids. (3) Add 429 RATE_LIMITED, with body retryAfter and the Retry-After header, to all writes, bulk-import, /students/search and the public school/JPN/PPD routes. (4) Restrict /students/search by role and scope, for example teacher, school_admin and admin in their own school, and require 3 characters. A parent or student should get no results or a 403. (5) Add max lengths and a row cap for bulk-import (csvFile and pasteContent), 413 and 422, and a max of 128 on all password fields. (6) Add mustChangePassword to the detail, the create response and the import report, per D55(c). (7) Document Cache-Control: no-store on all personal-data responses.
- Fix in the implementation card BE-05: keyed HMAC for ic_hash, with no clear IC in logs, error bodies or DB. Constant-cost responses for unique-check errors for non-admin callers. Revoke sessions on password change, deactivate, delete or role change. A last-admin and self-demotion guard. Audit rows with ids only. Rate-limit values from env (THROTTLE_*) once OQ-9 is answered. A global no-store interceptor with header tests. Strict unknown-key rejection. Cap the school search limit at 100. Check that the cascade delete is transactional.
- Open as decisions for the LEAD or user: erasure and retention of minors' data (OQ-3), the password policy (minimum 6), whether school_admin may call /admin/users at all (card rule 10 is ambiguous), and the shared default-password model.
