## Security re-review (Fail)

- FIXED - mustChangePassword (D55c): SchoolAdminPupilCreatedResult now has `mustChangePassword: z.literal(true)` with documentation. The POST /admin-sekolah/pelajar description states that the password is shown once, never logged, never stored in plain text and not retrievable again. Residual gap (Low, contract now): the default-password case is not covered. An empty `password` still means the shared configured default, and that default is echoed back in credential.password. The flag covers the first login, but a printed hand-out of the default is still a shared secret for minors until each pupil logs in. D57(c) is satisfied only through the flag.
- HIGH - contract now - 429 RATE_LIMITED is not declared on any of the 24 routes. A grep of paths.ts, common.ts and the other school-admin files finds no 429, no RATE_LIMITED, no retryAfter and no Retry-After. This breaks D57(a) and BE-NFR-04. The riskiest routes are POST /pelajar (bulk minting of minor accounts, and e-mail probing through 422), POST /guru, both reset-password routes and both export.csv routes (bulk dump of minors' names and e-mails). Recommendation: add a shared RATE_LIMITED response, with a body that carries retryAfter and a Retry-After header, to every POST/PUT, both reset-password routes and both export.csv routes. The numeric limits go in the implementation card and the runbook.
- HIGH - contract now - Cache-Control: no-store is missing on the credential response. The only Cache-Control header in the whole domain is on the Amaran school CSV (paths.ts line 523). The 201 from POST /admin-sekolah/pelajar carries credential.password in the body but declares no header. This breaks D57(b). The user CSVs (guru and pelajar export.csv) also declare none. A proxy or browser cache could keep a minor's plaintext password or a roster of minors. Recommendation: declare `Cache-Control: no-store` (and `Pragma: no-cache`) as response headers on the 201, on both user CSVs and on both reset-password responses, and add a contract test that asserts them.
- MEDIUM - contract now - the retry path for the one-time credential is not documented. If the 201 is lost, a retry returns 422 'The email has already been taken.', the account exists and the password cannot be re-read. The create description says 'not retrievable again' but names no recovery. Recommendation: add a sentence to the 201 description saying that reset-password (POST /pelajar/{id}/reset-password) is the only recovery and that the credential is never re-served. Optionally accept an Idempotency-Key header (BE-NFR-18). The implementation must not store the plaintext to support a retry.
- MEDIUM - contract now - password policy is still inconsistent. Create pupil requires 8 to 255 characters (pupils.ts), but password6 in users.ts (update pupil/teacher newPassword, reset-password newPassword) and the create-teacher password (teachers.ts) use min(6) and have no maximum. A school admin can set a 6-character password on a minor's account, and an unbounded string reaches the hasher (DoS). The form-options already advertise passwordMinLength 8. Recommendation: use min(8).max(255) on every password field, or record the 6 as a deliberate mock-fidelity deviation in docs/architecture/v2-backend-deviations.md.
- MEDIUM - contract now - e-mail enumeration across schools is undocumented. Create and update answer 422 'The email has already been taken.' when the address belongs to any school, so a school admin can probe whether any e-mail, including a minor's, is registered. This cannot be hidden without dropping uniqueness. Recommendation: record it as an accepted trade-off in the contract description, mitigated by the 429 above and by audit events.
- MEDIUM - contract now - the card and the contract disagree on the admin role. Card AC1/AC8 say school_admin 'and admin'. The M27 routes use FORBIDDEN_SA (every role except school_admin gets 403) and admin has no school to scope to. Recommendation: exclude admin from /admin-sekolah/* in the card (safer, and consistent with 'a missing school never means all schools'), and amend the card.
- MEDIUM - contract now - self-lockout is not on the wire. AC3 says toggle-active cannot disable the caller's own account, but the toggle route lists only 401/403/404 and no refusal for a self-target. Recommendation: document one error (for example 403 with the roleNotManaged text, or 404) so backend and frontend agree.
- LOW - contract now - PDPA data minimisation for minors: `phone` (nullable string) is still in the list row shapes (SchoolAdminPupilRow, users.ts line 82 and pupils.ts line 19) even though the pupil CSV omits it. IC is correctly absent from every request and response (BE-NFR-10/11). Recommendation: drop `phone` from the pupil list row and keep it in the detail only. Add a short PDPA note to the two user CSVs and the Amaran pupil lists, which show names with risk scores.
- LOW - contract now - Amaran routes mix 404 and 403. An unknown school id is 404 (checked first) but another school's id is 403, so a caller can enumerate valid school ids. BE-NFR-05 says out-of-scope is 404. The card calls this a listed deviation. Recommendation: either answer 404 for both on /amaran/schools/{id} and /amaran/export/school/{id}, or record the exception in the deviations register. Reorder the CSV route so the access check comes before the unknown-school 404.
- LOW - contract now - role and scope rules are mostly sound. Same-school/other-school/unknown id all give the same 404; scope is derived from the session, with no schoolId in the M27 requests; role/school/status/icNumber extras are ignored; passwords are marked writeOnly; the Amaran CSV carries no-store. Note that ignoring unknown keys conflicts with BE-NFR-05 (strict schema, 422), so the waiver must be written in the card.
- LOW - implementation card - things the wire cannot enforce. Redact password, newPassword and credential from logs, APM and the 422 fields echo. Use argon2id. Write audit events for pupil create, teacher create, reset-password and both CSV exports (BE-NFR-08 does not list exports). Add mass-assignment tests (role=admin in the body still creates a student, classId from another school gives 422). Add a log-capture test with no password in logs. Add a session-revocation test after reset.

Recommendations:

Add before merge, all in the contract: (1) 429 RATE_LIMITED with retryAfter and the Retry-After header on every write, both reset-password routes and both export.csv routes; (2) Cache-Control: no-store on the pupil 201, on both user CSVs and on both reset-password responses, with a test; (3) one sentence on the lost-credential recovery via reset-password.
- Align every password field to min 8 and max 255 (users.ts password6, teachers.ts create), or log the 6-character minimum as a deliberate deviation.
- Drop `phone` from the pupil list row (keep it in the detail). Document the cross-school e-mail enumeration as an accepted trade-off. Document the self-toggle refusal. Exclude admin from /admin-sekolah/* in the card. Decide 404 or a recorded exception for out-of-scope Amaran school ids.
- Decide the default-password policy. Preferred: the server generates a random initial password per account and returns it in the same credential.password field, so the wire shape does not change. If the shared default stays, record it as an accepted risk.
- Put in the implementation card: log and error-body redaction, argon2id, audit events including exports, the numeric rate limits in the runbook, and the mass-assignment, cross-school and log-capture tests.
