## Goal

Everything the prototype serves under `/api/games/*`, `/api/papan-bijak/*`, `/api/leagues*`, `/api/sekolah-bersaing` and `/api/admin/games*`: the Permainan hub, the six room games (Papan Bijak, Perang Fakta, Benteng Ilmu, Perlumbaan Matematik, Kuiz Relay, Teka Silang Kata) with bot players, the Papan Bijak quick match, the five single-player games, Roda Nasib, Jutawan Ilmu, the weekly competition board, Uji Minda (constant), leagues, the Sekolah Bersaing weekly board and the admin game settings. Opponents and teammates are **deterministic bots, exactly as the mock codes them** (LEAD rule, TRACKER D53). Real-time multiplayer is not built (Open question 2).

**Why this split.** See the split explanation in [BE-44](BE-44-battle.md): BE-44 owns the 25 battle, standings and tournament routes; BE-45 owns the 27 games, leagues, Sekolah Bersaing and admin game routes. Separate Nest folders (`modules/games`), Prisma file (`games.prisma`), contract folder (`games/`), seed and test folders; every table has one owner card.

## Acceptance criteria

Replay the cases of the mock tests listed in Inputs. Exact BM messages are those of the mock.

1. **Guards.** No session: 401 `UNAUTHORIZED` "Unauthenticated." on every route. M16-51 and M16-52: 403 `FORBIDDEN` "This action is unauthorized." for every non-admin role. A mutating call without CSRF gets 403 `CSRF_INVALID`.
2. **Response styles.** Raw routes: M16-29 to M16-31, M16-33, M16-35. Raw error bodies: M16-29 `{error: "<BM>"}` with 422; M16-33 `{message}` with 409 / 404 / 422; M16-35 `{success: false, message}` with 409. All other routes use `{data}` and the standard `{error: {code, message, fields?}}` body, 422 `VALIDATION_ERROR` with `fields[<field>]` = message and the same top-level message. The contract declares both shapes per route; every response in tests is parsed by its contract schema.
3. **Hub (M16-22).** `openRooms`: up to 6 newest `waiting` rooms that still have a free seat, newest first (code ascending as tie-break), each `{game, code, host (name), players, max}`; `chips {papanBijakPlayed, battled}` where `papanBijakPlayed` = the caller has a Papan Bijak standing with `jumlah > 0` and `battled` comes from `BattleReadService.hasBattled`.
4. **Lobby (M16-23).** Unknown `:game` 404 `NOT_FOUND` "Permainan tidak dijumpai.". Body `autoGrade` (the caller's grade as `DARJAH_n` / `TINGKATAN_n`, null without a grade) and `autoGradeName` ("Darjah n" / "Tingkatan n" / null). `papan-bijak`: `top10[]` of standings with `jumlah > 0`, order wins desc, skor desc, then creation order; each `{rank, userId, name (truncated to 15 characters + "..."), initials (first letters of up to two words, upper case), menang, jumlah, kadar (round(menang / jumlah * 100), 0 when jumlah is 0), skor, betul}`. Other games: `leaders[]` top 10 with `wins > 0`, order wins desc, creation order, `reached_at` asc, each `{rank, userId, name, value}`.
5. **Create room (M16-24).** Validation order and messages: `subject` must be an allowed subject (Papan Bijak excludes `SEJARAH`) else 422 "Subjek tidak sah." (`fields.subject`); `grade_level` a valid `DARJAH_n` / `TINGKATAN_n` else "Tahap soalan tidak sah." (`fields.grade_level`); `match_mode` `same_grade|same_level` (plus `custom` for Papan Bijak only) else "Julat tahap tidak sah." (`fields.match_mode`); `custom` needs integer `grade_min <= grade_max` within 1..11 else "Julat tahap tidak sah." (`fields.grade_min`); Papan Bijak needs integer `max_players` 2..6 else "Bilangan pemain tidak sah." (`fields.max_players`), other games use their fixed maximum (Perang Fakta 6, Benteng Ilmu 2, Perlumbaan Matematik 4, Kuiz Relay 8, Teka Silang Kata 2); unknown game 404 "Permainan tidak dijumpai.". Success 201 `{data: {code}}`; the caller is host and first (human) player; room `waiting`.
6. **Join room (M16-25).** Body `room_code` trimmed and upper-cased. Every refusal is 404 `NOT_FOUND` "Bilik tidak dijumpai." (blank code, unknown room, other game, room not `waiting`, room full, caller's grade not allowed by the match mode: `same_grade` equal grade, `same_level` same primary/secondary side, `custom` inside `grade_min..grade_max`; a caller without a grade always fits). Already a player: 200 with the same code, no second row. Success `{data: {code}}`. Concurrent joins never exceed `max_players` (row lock, test).
7. **Room view (M16-26).** Only players of the room (others 404 "Bilik tidak dijumpai."). Shape of the catalogue (`RoomView`): `players[]` with `{id, name, grade, team?, points, isBot}`, `settings`, `state` (null while waiting), `round`, keyless `question`, `result` when finished. **Simulation on read:** a poll by the host of a `waiting` room below the game's minimum players (2, Kuiz Relay 4) adds exactly one bot player per poll (a fictitious student of a fitting grade not already in the room, picked from a named PRNG stream); server clocks advance or finish timed games on read (Perang Fakta 10 s rounds, Teka Silang Kata 5 minutes) and a game finished that way settles its rewards exactly once.
8. **Start room (M16-27).** Host only: 404 "Bilik tidak dijumpai."; 403 `FORBIDDEN` "Hanya hos boleh memulakan permainan."; room not `waiting` 409 `CONFLICT` "Permainan sudah dimulakan."; below the minimum players 409 "Pemain belum mencukupi."; fewer eligible questions than the game needs 409 "Soalan tidak mencukupi."; success returns the `playing` room view. The question pool is drawn through BE-09 `QuestionsService` for the room subject and the host's level.
9. **Room actions (M16-28).** Body `{type: "roll"}` or `{type: "answer", questionId, optionId?, value?, seconds?}` (`seconds` default 15). Errors: 422 "Soalan tidak sah." (`questionId`), "Pilihan tidak sah." (`optionId`), "Masa tidak sah." (`seconds`), "Tindakan tidak sah." (`type`), "Soalan tidak sepadan." (`questionId`), "Jawapan tidak sah." (`value`); 409 "Permainan belum bermula.", "Bukan giliran anda untuk gulung dadu.", "Tiada soalan untuk dijawab.", "Tiada jam untuk permainan ini."; 403 "Bukan giliran anda." (only the room's human, the host, acts: in the mock every other player is a bot; Open question 2); 404 "Bilik tidak dijumpai.". If a server clock ended the game just before the action, the finished room is returned instead of an error. The engine is the pure port of `room-engine.ts` (Papan Bijak 50-tile board with the 3 ladders, 3 snakes, 2 bonus, 2 traps and the quiz tiles from `game_settings`; Perang Fakta 15 rounds; Benteng Ilmu 100 HP and 20 damage; Perlumbaan Matematik 20 steps; Kuiz Relay 10 rounds in two teams; Teka Silang Kata 8 words); the same room and the same actions give the same game under the same seed (named streams `m16:room:<code>:...`). Bot answers are correct with probability `p`, the platform answer accuracy from the practice owner's service. Unit tests replay `__tests__/mock/rules.test.ts` and `room-clocks.test.ts`.
10. **Settlement.** On finish, once per room: `game_standings` get `wins` +1 for the winner (Kuiz Relay: the MVP) and, for Papan Bijak, `jumlah` +1 and `betul` / `skor` added for every player; one M14 `onGameResult` for the acting human with game token, event and coins: Papan Bijak coins = correct answers x tier `boardGameRewardCorrect` + (win ? tier `boardGameRewardWin` : 0) with events `correct` / `win`; Benteng Ilmu 8 played / 35 won (events `play` / `win`); Perang Fakta 10 on a win; Perlumbaan Matematik 5 (event `play`, detail rank); Kuiz Relay and Teka Silang Kata 0. XP is always 0. Syiling are credited only when `games_award_syiling` is on and the user's coins are enabled (`canEarnSyiling`), through the owner service (Open question 1); ledger source and description follow the M14 `gameRow` wording (for example `benteng_win` "Juara Benteng Ilmu!", `papan_bijak_win` "Menang Papan Bijak! 🏆🎲"), idempotent per room and user so a replayed poll never pays twice.
11. **Papan Bijak quick match (M16-29 to M16-31).** Start: `subject` in `MATEMATIK|BAHASA_MELAYU|SAINS|BAHASA_INGGERIS` else 422 `{error: "Subjek tidak sah."}`; `match_mode` `same_grade|same_level` else `{error: "Padanan tidak sah."}`; success `{status: "searching"}`. Poll: the caller's latest search; none or cancelled = `{status: "cancelled"}`; older than 120 s = `expired`; the **third poll matches**: a Papan Bijak room is created (host = caller, 4 seats, the caller's grade level, a bot player added) and the answer is `{status: "matched", room_code}`; before that `searching`. Cancel always answers `{status: "cancelled"}` and turns a `searching` row into `cancelled`.
12. **Solo games (M16-32, M16-33).** Unknown game 404 "Permainan tidak dijumpai."; `darjah` 1..11 (default the caller's grade, else 4; ignored by `kad-memori`, which uses levels 1 to 4), else 422 "Tahap tidak sah." (`fields.darjah`). The payload (`sessionId`, `personalBest`, `canEarnSyiling` and the items by game: `statements[]` 40, `questions[]` 30, `puzzles[]` 20, `cards[]` 12 as the catalogue) is drawn from published MCQ through `QuestionsService.sample`; **as in the mock, the payload carries the answer keys** (SEC-M16-01; Open question 8). A session row is created by the GET (SEC-M16-11, replicate). Submit: own session only; body per game; the server bounds of the catalogue (counts at most the items served, streak / combo at most correct, max level within `1..1+floor(correct/5)`, score at most the game maximum for that many correct answers: Betul/Salah `sum(10 + min(k,10)*2)`, Cabaran Kilat `sum(10*min(k,10))`, Tembak Jawapan `sum(10*(1+floor((k-1)/5)))`, Susun Jawapan the sum of served puzzle points, `syiling_earned` at most 5 x correct / 10 x correct / floor(maxScore/10); Kad Memori `matches` and `total_pairs` equal 6, `moves` at least 6) else 422 `{message: "Keputusan tidak sah."}`; second submit 409 `{message: "Keputusan sudah dihantar."}` (concurrent double submit: exactly one succeeds, test); success `{is_new_record, syiling_awarded}` or, for Kad Memori, `{results: {syiling_earned, accuracy}}` with accuracy `round(6 / moves * 100)` and coins 6. A first result is a record, later ones only if they exceed the stored best. Coins go through `onGameResult` once, only when `canEarnSyiling`.
13. **Roda Nasib (M16-34, M16-35).** Page: the 8 fixed segments in order ("1 Syiling", "3 Syiling", "5 Syiling", "10 Syiling", "20 Syiling", "Cuba Lagi", "2 Syiling", "7 Syiling") with weights 25/20/15/8/3/15/10/4, `spins`, `won`, `alreadySpun` (a spin on today's Malaysia date), `canEarnSyiling`. Spin: one per Malaysia day enforced by the unique `(user_id, spin_date)` constraint; a second spin the same day 409 `{success: false, message: "Anda sudah spin hari ini."}`; the segment is drawn server-side by the weights from a named PRNG stream; answer `{success: true, message: "", result: {segment_index, label, icon, type, value}, coinsCredited}`; game `roda_nasib`, event `spin`, coins = the segment value for `syiling` segments (credited only when allowed). Two concurrent spins: exactly one succeeds (test).
14. **Jutawan Ilmu (M16-36 to M16-39).** Page: `bestLevel`, `games`; with `darjah` also `heading` ("DARJAH n" for 1 to 6, "TINGKATAN n" for 7 to 11) and `subjects[]` (id, name, emoji, colour, question count at that level; the 10 observed tile emojis and colours in `mock/data/games.ts`, fallback emoji and colour for the others); invalid `darjah` 422 "Tahap tidak sah." (`fields.darjah`). Start (200, not 201): `darjah` 1..11 else "Tahap tidak sah.", `subject` valid else "Subjek tidak sah.", fewer than 15 questions "Soalan tidak mencukupi." (`fields.subject`); returns `{sessionId, index: 1, question (keyless), lifelines: 3}`; difficulty ladder 1 for Q1-4, 2 for Q5-8, 3 for Q9-12, 4 for Q13-15. Answer: own session only; errors 404 "Sesi tidak dijumpai.", "Soalan tidak dijumpai."; 409 "Permainan sudah tamat."; 422 "Soalan tidak sepadan." (`questionId`), "Pilihan tidak sah." (`optionId`); a wrong answer or level 15 ends the game with `result {level, credited}`, otherwise `next`. On end: best level and games count updated, `onGameResult` game `jutawan`, event `finish`, coins 1000 for level 15, 50 for levels 10 to 14, otherwise 0 (PROPOSED ladder in the SRS; Open question 6), ledger wording "Jutawan Ilmu ({subjek}): Level {n}". Lifeline: body `{type: "50:50"}` else 422 "Bantuan tidak sah." (`type`); 404 "Sesi tidak dijumpai."; 409 "Permainan sudah tamat." or "Tiada bantuan tersedia." (none left, or already used on this question); returns `{removedOptionIds: [two wrong options], lifelines}` and remembers the removal for the current question.
15. **Weekly competition and Uji Minda (M16-40, M16-41).** `{weekStart, weekEnd, endsAt (Sunday 23:59:59 +08:00), prizes: [100, 50, 25], me: {rank, betul} | null, rows[] (top 20: rank, userId, name, sesi, betul, tepat)}` from the practice owner's weekly ranking read (BE-13); Uji Minda always `{data: {challenge: null}}`.
16. **Leagues (M16-46 to M16-49).** List: `{mine, open}` cards (`id, name, status, statusLabel, scopeLabel, typeLabel, subjectName | null, startDate, endDate, schools`); `mine` = leagues containing the caller's school; `open` = every league not `ended`. Create (201 `{id}`): any signed-in role; 422 with top-level message = the first field message: required fields (`name` 1..255, `type`, `scope`, `game_mode`, `scoring_method`, `start_date`, `end_date`) "Sila lengkapkan semua medan wajib."; `end_date` before `start_date` "Tarikh tamat mesti selepas tarikh mula."; `max_schools` outside 2..500 "Had sekolah mesti antara 2 dan 500."; unknown `subject_id` "Mata pelajaran tidak sah."; invalid `class_levels` "Tingkatan tidak sah."; result: league `upcoming`, an 8-character invite code (A-Z0-9, unique, retried on collision) and the creator's school (if any) added as a participant. Join (`invite_code` trimmed, upper-cased): 422 `fields.invite_code` "Kod jemputan tidak sah.", "Liga ini sudah tamat.", "Anda perlu mempunyai sekolah untuk menyertai liga ini.", "Sekolah anda sudah menyertai liga ini.", "Liga ini sudah penuh."; success `{id}`; concurrent joins never exceed `max_schools`. Detail: 404 `NOT_FOUND` "Liga tidak dijumpai."; fields as the catalogue including `canJoin` (not ended, caller's school not in, not full), `inviteCode` and `shareUrl` visible to non-members (as live), `standings` as a map of class level to rows for the levels that have rows. League `status` is stored and not moved by dates (Open question 7).
17. **Sekolah Bersaing (M16-50).** Query `week`: a valid `YYYY-MM-DD` selects the Monday of that week; anything else the current week; never a 500 (SEC-M16-09). Body `{weekStart, count, rows[]}` with rows in stored rank order `{rank, schoolName, state, aktifPct, streakAvg, notaPer10, anonymous}`; an anonymous row shows `schoolName` "Sekolah anonim"; an empty week returns `rows: []`.
18. **Admin settings (M16-51, M16-52).** `GET` returns `{stats {rooms, playing, finished, players (distinct users in rooms)}, settings {boardgameQuizTiles}}`. `PUT` body `{boardgame_quiz_tiles: integer 0..38}`, else 422 `VALIDATION_ERROR` "Nilai mesti antara 0 dan 38." (`fields.boardgame_quiz_tiles`); returns `{data: {boardgameQuizTiles}}`. The mock writes no audit event; whether an admin change must be audited (BE-NFR-08) is a question for the lead and none is built here.
19. **Wallet safety.** Every coin movement goes through the owner service in the caller's transaction and is idempotent per `(source, source_id)`; a failed game transaction leaves no ledger row. No code in this card writes `wallets` or `coin_ledger`.
20. **Determinism and time.** Code reads the injectable `Clock` and the seeded PRNG, never `Date.now()` or `Math.random()`; day logic (spin, weekly board, Sekolah Bersaing week) is in Asia/Kuala_Lumpur.

## Open questions

Do not guess these; write your working assumption in the PR and ask the lead (issue labelled `question`) if it blocks you.

1. **Who exports the M14 entry points `onGameResult` and `canEarnSyiling`?** The M14 contract (ADR-0014, build plan) names them (coins credited only when `games_award_syiling` = 1 and the user's coins are enabled; Papan Bijak coins from the tier rates; the ledger wording of `gameRow`), but neither BE-11 nor BE-23 lists them. Working assumption: BE-23 exports `GamificationService.onGameResult` and `canEarnSyiling`; this card codes against that interface with a test double, and does not write the ledger itself. If the lead decides otherwise, the fallback is a thin `GameRewardService` inside `modules/games` that calls `WalletService.credit` with the sources and descriptions of AC 10 and reads the setting and the tier rates through BE-23's readers.
2. **Real-time multiplayer is not invented.** The mock polls every 3 s and simulates every other player with bots; only the room host (the "human") may act, so a second real player who joins a room by code can watch but not play. There is no websocket, no matchmaking between two real people and no push (OQ-API-B4-11). Working assumption: ship exactly this; production behaviour is the lead's decision.
3. **Who is a bot?** The mock's bots are existing fictitious students from the users dataset, shown with their names. With real pupils that would present a real child as a player who never played. Working assumption: replicate the pick through the BE-05 service, store `is_bot = true`, and do not expose another flag. The lead decides before production whether bots use dedicated accounts or a neutral display name (same question as BE-44, Open question 3).
4. **Hub chip dependency on BE-44.** `battled` needs `BattleReadService.hasBattled`. Working assumption: stub returns false until BE-44 merges; the stub test is named so it is removed then.
5. **Subject mapping.** The mock maps the five room subjects to M03 ids (`MATEMATIK` 3, `BAHASA_MELAYU` 1, `SAINS` 4, `BAHASA_INGGERIS` 2, `SEJARAH` 5) and bounds solo and tournament subjects by id 1..31. v2 ids are opaque. Working assumption: map by subject code through BE-08 (the `SPM_COUNTS` keys in `mock/data/constants.ts` are codes) and store the English room-subject code on the room; the BE-08 seed fixes the set.
6. **PROPOSED rules in the SRS.** The room rules (BR-M16-20), the Jutawan ladder (1000 at level 15, 50 at levels 10 to 14), the Roda Nasib weights and the refusal copy are marked PROPOSED or PROVISIONAL in the SRS; the live values were not observable. Working assumption: build them as the mock has them; the lead confirms or changes them in the SRS.
7. **Stored boards without a job.** League standings and Sekolah Bersaing weekly rows are stored job output in the mock; the job (formula, inputs from practice and streaks, anonymity flag) is undefined (OQ-API-B4-14; OQ-M16-09), and league `status` never moves by date (OQ-API-B4-13). Working assumption: B1 serves seeded rows only and builds no job; the lead defines the jobs before they are carded. Leagues are also marked Hidden-OOS in `v2-cloud-gap.md` F-61 (owner M26); the routes are built because D53 puts every prototype-reachable route in B1, but the lead should confirm that the frontend exposes them.
8. **Answer keys and client-side scoring.** The solo payload ships `is_true`, `correct`, `answer` and `pair_id`, and the client posts its own score and coins (SEC-M16-01, SEC-M16-11). The card replicates this with the server-side plausibility bounds of AC 12. A hardened design (server scoring, sessions created by POST) is a later decision; coins are only credited when `games_award_syiling` is on, which is the control the product uses today.
9. **`.cloud` migration choices.** Whether completed rooms, game sessions and `.cloud` leagues are migrated (data migration 4.10, Q13) is the lead's decision; the proposed matrix above migrates `game_sessions` only.
10. **Data model docs.** M16 tables sit in data model section 3.13 (backlog). The lead moves them into a new section (proposed 3.14 "Battle and games"), adds them to the ownership table 2.2 and the Prisma file list, records the G-11 exception for `game_rooms.state`, and adds the lane row to sessions.md section 5. This card does not edit those files.
11. **Consumers and Admin Sekolah.** BE-20 (M11) needs `GameReadService`; its card does not list it yet. The Admin Sekolah menu item "Sekolah Bersaing" (matrix row 45, D-RAM-2) calls `GET /api/sekolah-bersaing` with the admin-school session; the route has no school scope in the mock (national board), as the catalogue states.
12. **Privacy of minors.** Lobby leaderboards, room players and the weekly competition show full names of pupils (OQ-API-B4-4; SEC-M16-07 recommends first name + initial and opt-out). Working assumption: replicate; the `anonymous` flag of Sekolah Bersaing rows is honoured when set.
