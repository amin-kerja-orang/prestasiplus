### R1E2E-17 (Medium, team A; field team C): an unknown SP code typed in the intake editor passes every gate and is silently dropped
- Steps: Muat Naik Kertas, upload a PDF, Ekstrak; on a card pick a real unit (e.g. `T4 - 1.0 Fungsi dan Persamaan Kuadratik…`), type SP `1.1` (the field hint is "cth. 3.1, 3.2"; real SP codes of that unit are `1.1.1`, `1.1.2`, …), TP 3; Hantar untuk semakan → accepted; Baris Gilir Semakan → Terima (Draf); Bank Soalan → Hantar untuk Semakan → bulk Terbitkan.
- Expected: the intake gate refuses an SP that is not in the unit (as it refuses an unknown unit), or the SP is picked from the unit's list.
- Actual: the batch and the item pass; the bank question has `tag.spIds: []`; approval is refused "Sila pilih sekurang-kurangnya satu SP DSKP." long after the intake screen. Seen in a debug run on a fresh DB (mobile); the reported run types a real SP code (`1.1.1`, read from the DSKP list) to test the rest of the path.

- S2b rewritten for http mode: "Terima (Draf)" (`action-publish`) per queue item (card tap below the table breakpoint), waiting for the queue to reload; moved before S2a so the accepted questions go through the UI approval.
- S2g (new, **UI workaround**, labelled): Aras pemikiran set in Studio "Sunting" on the intake questions (R1E2E-12).
- S2a: counts every run question, reports approval per entry path, expects all but the untagged CSV rows (refused by design) to approve. S2c reports per path.
- S3e: places the approved intake D90 group at the end of Bahagian A (marks of the generated questions adjusted to the budget).
- S4b: checks the shared passage on each member screen (inline from `lg`, chip → drawer below) and on the result (split pane or chip → drawer), once.
