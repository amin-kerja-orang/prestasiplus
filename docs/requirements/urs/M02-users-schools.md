**Conventions** (same as M01)
- Quoted UI copy is the exact live text as displayed: Bahasa Melayu (BM), or English where the live site is English (pagination summary, "Login As", "Upload CSV", "Paste Manual", browser-native validation bubbles).
- **OBSERVED** = seen on the live site (walkthrough, inventory state, or page script). **INFERRED** = the live site does it but it could not be observed read-only (every POST outcome, impersonation, toggled labels, cancelled/expired/grace subscription pages, import results). For INFERRED behaviour the most likely live behaviour is specified (Laravel defaults where they apply) and no new UX is invented.
- **UNVERIFIED COPY** = the text of a message shown after a submit, which could not be captured. The prototype uses the placeholder given in SRS §8 until verified (§9 OQ-1).
- **DV-M02-nn** = a fidelity deviation decided under rule D9 (§7). Anything not listed there must match the live site.
- **SEC-M02-nn** = a security risk of the live behaviour, replicated in the prototype with dummy data and recorded for security-engineer review before the backend phase (SRS NFR-M02-04).
- Personal data: the discovery masked all people (`<name>`, `<email>`, …). This URS quotes structure and UI copy only. Real, public school names appear only where the inventory quotes them. Fixed default passwords shown by the live UI are **never** written: they appear as `<default-password-A>` (school-admin generator), `<default-password>` (bulk-import placeholder) and `<default-password-comp>` (complimentary students, 8 digits).

## 1. Overview

M02 is the admin panel's "Pengguna" sidebar group. With it an admin:
- lists, filters, creates, edits, activates/deactivates, deletes (one or in bulk) and impersonates user accounts of 8 role types;
- links parents to their children (the only place in the system where this happens — answers M01 Q8);
- generates school-admin accounts from a school's KPM code and assigns SPM packages to a school admin;
- imports teachers, parents, school admins and PPD officers in bulk (CSV or paste), and imports students by DELIMa ID within a school's subscription quota;
- registers "complimentary" (QA-assistance) students with a free full package and coins disabled, and manages them;
- manages the school register (10,220 schools on live; answers M01 Q12 on school types);
- manages school SPM subscriptions (create, quota, extend, upgrade, cancel) and prints a renewal invoice. The payment money flow belongs to M19; M02 only records the payment reference text.

The rebuild replicates the live behaviour exactly (D7), as a front-end prototype with dummy data and a mock service layer (D1, D2).

### Acceptance criteria

**US-M02-01 — User list**
- **AC-M02-01.1** Given I open `/admin/users`, when it loads, then the shell header shows "Pengurusan Pengguna" / "Urus akaun pengguna PRESTASIPLUS" and the tab title is "Pengurusan Pengguna - Admin Panel".
- **AC-M02-01.2** Given the stat cards, when the page loads, then I see 7 cards in this order, each with its icon circle, the count and the label: Pelajar (`fa-user-graduate`, blue), Guru (`fa-chalkboard-teacher`, purple), Ibu Bapa (`fa-users`, amber), Penaja (`fa-hand-holding-heart`, emerald), Admin Sekolah (`fa-school`, teal), Pegawai PPD (`fa-building-columns`, cyan), Admin (`fa-user-shield`, red). Each card links to `/admin/users?role=<code>`. At every width each label is shown in full, never cut with "..." (DV-M02-02; live truncates all 7 at 1280).
- **AC-M02-01.3** Given the table, when it loads, then it has the columns [checkbox] "#", "Nama", "Emel", "Telefon", "Peranan", "Sekolah", "Aktif?", "Tarikh", "Tindakan" and 25 rows per page, newest first. Each row shows the running number, a generated initials avatar with the name, the email, the phone or "-", a role badge with the BM label, the school name or "-", the "Aktif?" toggle, the registration date as `dd/mm/yyyy`, and the row actions.
- **AC-M02-01.4** Given a user whose role is `jpn_officer`, when the row shows, then the badge reads "Pegawai JPN", not the raw code (DV-M02-03).
- **AC-M02-01.5** Given more than 25 users at ≥640px, when I view the pagination, then I see "Showing {from} to {to} of {total} results", numbered links with "..." gaps (Laravel window, e.g. 1–10 … last two) and chevron previous/next links. Page links keep every active filter (e.g. `?role=student&page=2`).
- **AC-M02-01.6** Given a width below 640px, when I view the pagination, then I see "« Previous" / "Next »", shown as plain text when unavailable.
- **AC-M02-01.7** Given a width of 1280px, when the table renders, then the "Aktif?", "Tarikh" and "Tindakan" columns are visible without horizontal scrolling. Below 1280px the table scrolls horizontally inside its card (no pinned column), never the page, and its text is at least 12px (DV-M02-01).
- **AC-M02-01.8** Given the row of my own (logged-in) account, when it shows, then it has no checkbox, no "Login As" and no bin button; its "Aktif?" toggle, "Edit" (and "Pakej" when applicable) are present, as on live.

- **AC-M02-02.1** Given the filter card, when it loads, then I see "Peranan" (options "Semua Peranan", Pelajar, Guru, Ibu Bapa, Penaja, Admin Sekolah, Pegawai PPD, Pegawai JPN, Admin — "Pegawai JPN" added by DV-M02-03), "Sekolah" ("Semua Sekolah" + schools), "Status" ("Semua", "Aktif", "Tidak Aktif"), "Cari" (placeholder "Nama atau emel...") and the button "Cari" with a filter icon. - **AC-M02-02.2** Given the "Sekolah" select, when I open it, then it lists only the schools that have at least one user, alphabetically by name, with the school name as shown in the register (e.g. "SMK Leqoe" keeps its mixed case).
- **AC-M02-02.3** Given I set any combination of filters and press "Cari", when the list reloads, then the URL carries `role`, `school`, `is_active` and `search`, the controls keep their values, and only matching users are listed. `search` matches part of the name or the email.
