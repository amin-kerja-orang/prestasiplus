**Conventions** (same as M04–M06)
- Quoted UI copy is the exact live text as displayed: Bahasa Melayu, or English where the live site is English (Laravel pager "Showing … results", "« Previous" / "Next »", the grant placeholder "User ID"). Where CSS upper-cases text, the displayed form is given.
- **OBSERVED** = seen on the live site (walk-through, inventory state, page markup or script). **SOURCE-DERIVED** = taken from live markup or copy that was captured read-only, for a state that was never rendered (e.g. the exam composition and weights from the hub copy). **INFERRED** = the most likely live behaviour, not observed (every POST outcome, the locked student view, practice and exam pages, server rules); no new UX is invented for it. **Provisional** = a prototype stand-in for a live page that works but was not observed (L-2, L-3); it asserts no unobserved UI detail and is replaced after the live session.
- **UNVERIFIED COPY** = live text that exists but could not be captured (post-submit flashes, validation messages, labels of expired/revoked access, pending/rejected pill colours). The prototype uses the SRS §8 placeholders until verified (§9 OQ-M07-02).
- **PROPOSED COPY** = new BM text written for a D9 fix where live has no working original (DV-M07-01 history page; the button "Hantar" of the provisional practice/exam pages). It needs the owner's acceptance at G1.
- **DV-M07-nn** = fidelity deviation (§7). Anything not listed there must match live. **SEC-M07-nn** = a risk of the live behaviour, replicated with dummy data and recorded for security review (SRS §11).
- **L-n** = a live-session state from discovery §9 that needs a student account or a submit (not observed). Each is mapped in §5.1.
- **D10:** accessibility (ARIA, keyboard, focus, motion) replicates live, with no enhancements. A deliberate, consistent limit is not "broken"; adding options to a working feature is new scope.
- Personal data: the live access list was masked in discovery (`<person>`, `<email>`). This URS quotes structure and UI copy only. Question texts are content, not personal data; short samples are quoted as data.
- `{L}` = `T1` or `T4`. `{CODE}` = a domain code `PKSK_*`.

## 1. Overview

M07 is the premium **PKSK** track (*Pentaksiran Kemasukan Sekolah Khusus* — the admin subtitle on `/admin/pksk/questions`). Students see it as **"Persediaan Kemasukan SBP / MRSM / SMKA"**: preparation for entry to fully-residential schools (SBP), MARA junior science colleges (MRSM) and religious secondary schools (SMKA), at two entry points: **T1** (entry to Tingkatan 1, sat in Darjah 6) and **T4** (entry to Tingkatan 4, sat in Tingkatan 3).

M07 has two halves:
1. **Student (user portal).** A hub with the exam format and two level cards; a dashboard per level (readiness score and grade, exam count, Bahagian B average, three shortcuts, mastery per Bahagian B domain); a domain list per level; exam history; and the entry points to domain practice and the full exam.
2. **Admin (admin panel, sidebar group "Premium").** "PKSK Soalan": question list with global stat cards, filters, bulk approve / reject / delete, create and edit. "PKSK Akses": grant a package to a numeric user id with an optional expiry, list and revoke grants.

**Content model (OBSERVED).**

| Bahagian | Name | Exam format (hub copy) | Domains | Answer model |
|---|---|---|---|---|
| A | Kecerdasan Insaniah | 30 soalan · Pemberat: 20% · "Nilai, akhlak & sahsiah" | 1 (Kecerdasan Insaniah) | Multiple choice with no right answer ("(Tiada jawapan betul/salah)"); existing records still store one option flagged correct |
| B | Kecerdasan Intelek | 70 soalan · Pemberat: 70% · "Kognitif & penaakulan" | 13 (Matematik … Isu Global) | Multiple choice, one or more options ticked "Betul" |
| C | Artikulasi Penulisan | 1 esei · Pemberat: 10% · "Penulisan kreatif" | 1 (Artikulasi Penulisan) | Essay prompt, no options |

Every question targets exactly one level (T1 or T4) and one domain; its Bahagian is its domain's Bahagian. There are no sets and no subjects. Live data: 763 questions (T1 383, T4 380; A 160, B 573, C 30), all approved. Access is granted per user as a package: T1, T4 or Kombo (T1 + T4).
