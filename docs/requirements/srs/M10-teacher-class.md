### 11.1 Security notes (backend phase)

| ID | Risk in the live behaviour (replicated with dummy data) | Backend requirement |
|---|---|---|
| SEC-M10-01 | **Broadcasts to minors.** A teacher sends free text (≤ 500) to all their students with no recipient choice, moderation, audit trail or rate limit visible. | Server-side length and content checks, per-teacher rate limit, audit log (sender, recipients, time), admin takedown; recipients limited to the teacher's enrolled students. |
| SEC-M10-02 | **Join codes.** Generated 6-character codes (~36⁶); stored anchors may differ ("DEMO-4S"); joined with a plain POST; the QR URL exposes the code; codes never rotate; `qr-data` for other classes returns a 404 JSON naming the model (`App\Models\Classroom`). | Rate-limit and lock out join attempts per user/IP; optional code rotation; generic 404 bodies without model names; enrolment only for students (role check). |
| SEC-M10-03 | **Remedial generation.** `remedial/generate {student_id, subject}` and `cancel {quiz_id}` take ids from the client; the scan returned a 500 HTML page (stack leakage risk). | Authorise: the student must be enrolled in the teacher's class and the quiz owned by the teacher; JSON error bodies only; CSRF on POST (present on live). |
| SEC-M10-04 | **Unmoderated links shown to minors.** Soalan & Rujukan and mission "Bahan Rujukan" URLs (any site) are embedded (YouTube/Anyflip/Canva iframes) or shown as buttons to students without review; `javascript:`/`data:` schemes are not visibly blocked. | Allow only `http(s)`, embed only allow-listed hosts with sandboxed iframes, `rel="noopener noreferrer"`, admin reporting/takedown, logging. |
| SEC-M10-05 | **CSV import.** Arbitrary CSV/TXT rows become pending questions; spreadsheet formula cells (`=`, `+`, `-`, `@`) could reach admin exports; size unbounded on the client. | Size/row limits, strict parsing, formula-injection neutralisation on export, per-row validation, the pending review of M04. |
| SEC-M10-06 | **File uploads.** Audio (`.mp3,.m4a,.wav,.ogg,.aac,.mp4,audio/*`), question papers (5 × 20 MB), article attachments (5 × 20 MB) and images are accepted by extension on the client. | Server MIME sniffing, size limits, malware scanning, storage outside the web root, content-disposition download, no execution. |
| SEC-M10-07 | **IDOR on `/guru/soalan/{id}`** (show, edit, update, delete) and on `/guru/soalan-berstruktur/{id}`, `/guru/artikel/{id}`: the admin opened ids it created; a teacher's access to other teachers' ids was not observable. | Enforce ownership (or role) on every read and write; 404 for others; never trust hidden `options[i][id]`. |
| SEC-M10-08 | **GET that may write.** Command Center "Evaluate" and "Badges" run on GET and are named "Penilaian Risiko" / "Scan & Award Badges". | State changes only via POST with CSRF; GET read-only (as the prototype does). |
| SEC-M10-09 | **Student data exposure.** `live-data`, `drill`, `predictive`, `live-kelas` return student names and performance for the teacher; the admin view is platform-wide. | Scope strictly to the teacher's classes; minimise fields; audit access. |
| SEC-M10-10 | **Rich text and HTML.** Article content (HTML editor), stimulus text and teacher questions are rendered to other users. | Server-side HTML sanitisation (allow-list), CSP (M09 notes), escape all plain-text fields. |
| SEC-M10-11 | **Profile changes.** Email (login identity) and IC number (password-reset factor, M01) change without re-authentication. | Re-authenticate or confirm email changes; protect IC as personal data (PDPA). |
| SEC-M10-12 | **Reports.** Any teacher report deactivates an MCQ at once (M04 BR-M04-12). | Rate-limit reports; admin review before deactivation for single-teacher reports. |
| SEC-M10-13 | **XSS in the Command Center script.** The live feed builds HTML with unescaped `f.time`, `f.student`, `f.subject` (other fields use `esc()`). | Escape every interpolated value (the prototype does, FR-M10-18). |
